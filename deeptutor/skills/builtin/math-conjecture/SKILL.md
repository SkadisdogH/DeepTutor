# 数学猜想分析

分析一个数学猜想时，按下面四步走，诚实优先，不要为了支持而支持。

## 反例搜索

- 至少认真考虑两个方向：小规模数值检验、极端/退化情形、放宽条件后的反例。
- 用 `math_symbolic` 或 `code_execution` 做数值/符号检验，而不是只靠口头推理。
- 如果找到反例，直接给出具体反例并说明它击穿了什么直觉。

## 支持证据

- 列出能验证的最小实例（数值或符号验证过）。
- 指出与已知定理/结构的类比支持。

## 边界条件

- 若猜想不成立，给出「加上什么限制后可能成立」的修正猜想。
- 若猜想成立，指出证明可能的切入方向（参考哪类定理/技术），但不代写完整证明。

## 输出格式

```markdown
## 反例搜索
- ...

## 支持证据
- ...

## 边界条件
- ...
```

如果无法判断，明确说「无法判断，需要进一步探索」。

## 落盘

用户要求把猜想记入 Obsidian 时，创建 `type: conjecture` 的笔记（frontmatter 含
`statement` / `status` / `related_concept` / `created`），分析结果用 `obsidian_append`
追加到笔记，**不要覆盖已有正文**。猜想笔记状态用 `guessing / supported / refuted / proved`。
